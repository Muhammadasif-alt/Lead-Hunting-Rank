# Technical Specification #9 — Memory + Knowledge Architecture (LOCKED)

## 1. Core Principle
System in things کبھی mix نہیں ہوگا: FACT/SIGNAL/HYPOTHESIS/MEMORY/KNOWLEDGE/LEARNING. Example: FACT company website=abc.com; SIGNAL company added 4 job openings; HYPOTHESIS company may be expanding; MEMORY prospect prefers email communication or prefers quarterly meetings or previously rejected due timing; KNOWLEDGE our Website Growth package starts at approved price X; LEARNING landscaping owners respond better to audit-led outreach. Every category has own authority level + lifecycle.

## 2. Two Different Brains
Sales Memory = external relationships (companies/people/conversations/preferences/objections/promises/opportunities/relationships). Knowledge Base = our business's approved truth (services/pricing/policies/FAQs/case studies/claims/competitor info/proposal blocks/internal documents). AI uses both but does not mix them.

## 3. Third Layer — Strategy Learning
Strategy Memory/Learning separate. Example: ICP X performs better than ICP Y; subject line family A had better qualified-reply rate. Not prospect memory.

## 4-6. Memory Architecture + Why ExtractionCandidate + States
Raw Event→Extraction→ExtractionCandidate→Entity Resolution→Evidence Link→Conflict Check→Freshness/Validity→Memory→Context Retrieval. AI output directly permanent memory nahi banega. Example: "Maybe call me sometime next month" → AI extracts preferred_contact_date=next month; first becomes ExtractionCandidate; then validation (correct entity?/correct interpretation?/enough confidence?/conflicts?/date resolvable?); then accept/review/reject. Candidates state: PENDING/AUTO_ACCEPTED/ACCEPTED/NEEDS_REVIEW/REJECTED/SUPERSEDED. Low-risk obvious auto-accept; sensitive/ambiguous require review.

## 7-14. Memory Types + Scope Examples
Types: COMPANY/PERSON/CONVERSATION/RELATIONSHIP/OPPORTUNITY/COMMITMENT/PREFERENCE. Company memory: uses agency currently/recently redesigned website/prefers quarterly/main concern lead quality/previous rejected due timing. Person memory: decision role/preferred communication style/asked about pricing/referred us to Sarah/prefers afternoon meetings. Conversation memory: main objection/questions answered/decision criteria/promised follow-up/next expected action — conversation history itself ≠ memory. Opportunity memory: budget discussion/decision process/stakeholder concerns/competitive context/proposal changes/commercial objections — should not automatically become company-global truth. Scope example: prospect says "For this website project our budget is $5k" → Opportunity Memory, not Company always $5k. Relationship memory: John referred us to Sarah/Sarah introduced Mike/Mike previously worked with our salesperson. Preference memory: prefers email/doesn't want phone calls/prefers Tuesday meetings/wants short proposals — must include source/observed_at/scope/confidence and appropriate expiry/revalidation.

## 15-17. Memory Record + Status + Evidence
Conceptual Memory: id/workspace_id/entity_type/entity_id/memory_type/subject/predicate/value/summary/confidence/valid_from/valid_until/observed_at/last_confirmed_at/status/source_type/source_id/created_at/updated_at. Status: ACTIVE/STALE/CONFLICTED/SUPERSEDED/INVALIDATED/ARCHIVED. Never simply overwrite important history. Memory→MemoryEvidence→Message/Meeting/Evidence/Human Note: AI can answer "Hum ye kyun samajhte hain?" with traceable source.

## 18-22. Facts vs Memory + Note vs AI Inference + Conflict
If Company employee count=40 → Fact. If Owner said too busy this quarter → Memory, possibly with associated signal/commitment. Human Note: "I think this client is difficult" is Note/subjective observation, not canonical memory fact. UI distinguishes Human Note/Verified Fact/AI Inference/Extracted Memory. Conflict: old "Preferred contact=Email" vs new direct "Please call me instead" → MemoryConflict; resolution considers freshness/directness/source authority/scope/explicit correction; new explicit preference may supersede old. MemoryConflict table: memory_a_id/memory_b_id/conflict_type/detected_at/resolution/resolved_by/resolved_at.

## 23-27. Temporal Memory + Commitment ≠ Memory + Types + States + Promise Extraction + AI Can't Forget Its Promises
Memory needs time awareness: "Contact me after January" → store not_before or temporal semantics rather than only text; scheduler/policy enforces. Commitment is operationally important, own lifecycle: WE_PROMISED/PROSPECT_PROMISED/MUTUAL. States: OPEN/WAITING/DUE/COMPLETED/BROKEN/CANCELLED. Promise extraction: inbound/outbound messages checked for Promise/Deadline/Expected response/Requested action; "I'll send you the pricing sheet tomorrow" → candidate commitment. AI cannot forget its promises: Before generating reply, Context Builder should include relevant open commitments; otherwise AI could say "I'll send that tomorrow" when already promised yesterday.

## 28-29. Relationship Graph + Employment Specialized
Separate structured graph: Entity A→relation→Entity B with relationships WORKS_AT/FORMERLY_WORKED_AT/REFERRED_BY/INTRODUCED_BY/REPORTS_TO/DECISION_MAKER_FOR/INFLUENCER_FOR/PARTNER_OF/RELATED_COMPANY. Do not replace Employment table with generic graph; Person→Employment→Company needs title/department/seniority/start-end dates/current/confidence. Relationship graph supplements.

## 30-42. Knowledge Base Purpose + Types + Item + Revision + Status + Draft + Service + Pricing + Authority + FAQ + Policy Distinction + Claims
KB answers: What do we sell?/How much cost?/Who good fit?/What claims can make?/What guarantees?/What policies?/How integrations work?. Types: SERVICE/PRICING/FAQ/POLICY/INTEGRATION/CASE_STUDY/COMPETITOR/CLAIM/DOCUMENT/PROPOSAL_BLOCK. KnowledgeItem: id/workspace_id/type/title/scope/status/authority_level/current_revision_id/owner_id/timestamps. Never silently overwrite approved business truth; KnowledgeRevision: knowledge_item_id/version/structured_content/source_document_refs/status/created_by/reviewed_by/approved_by/created_at/approved_at. Status: DRAFT/IN_REVIEW/APPROVED/STALE/CONFLICT/REJECTED/ARCHIVED. Only approved/current knowledge gets highest autonomous authority. AI can help generate draft KB content but AI generated ≠ Approved company truth; draft must not become pricing/policy authority. Service Knowledge structured: Name/Description/Ideal customer/Included work/Excluded work/Deliverables/Typical process/Dependencies/Restrictions; avoid only one huge Markdown. Pricing strongly structured: Service/Offer/Currency/Price type/Base price/Minimum/Maximum/Add-ons/Discount rules/Validity/Approval rules; free-form PDF alone insufficient for autonomous quoting. Pricing Authority hierarchy: Approved structured Pricing record > Approved current pricing policy > Approved proposal block > Old document > Unapproved note; unresolved conflict → AI autonomous quote BLOCK/ASK. FAQ canonical: Question/Approved answer/Applicable services/Allowed variations/Evidence or source/Last reviewed; AI can adapt wording while preserving meaning. Knowledge Policy vs System Policy Engine: KB "Our normal project turnaround is 3–4 weeks" describes business knowledge; System Policy Engine "AI cannot promise custom delivery date without approval" enforces authority. Approved claims: Claim/Evidence/Scope/Expiry/Allowed usage; "We've completed 120+ projects" only if evidence/approval; AI cannot invent performance claims. Prohibited claims maintained: never say "Guaranteed #1 on Google" etc.; message validator checks.

## 43-46. Case Studies + Competitor + Battlecards + Proposal Blocks
Case study structured: client/anonymous identifier/industry/problem/work performed/outcome/metrics/evidence/allowed public claims. Competitor knowledge: name/known positioning/publicly sourced differences/approved comparison points/last reviewed; avoid defamatory/unverified claims. Battlecards: competitor/typical objection/approved response/evidence/do-not-say guidance — Conversation Agent retrieves only when relevant. Proposal blocks reusable approved sections: scope/deliverables/timeline language/terms/case-study section/pricing explanation/next steps; proposal generation becomes controlled assembly + customization.

## 47-57. Ingestion Pipeline + Document Not Truth + Candidate + Authority Hierarchy + Conflict + Types + Gap + Gap Record + Lifecycle + Don't Hallucinate
Pipeline: Document/Human Input/Integration→Ingest→Parse/Extract→Structured Candidates→Conflict Detection→Review→Approve→Version→Publish. Documents: PDF/DOCX/Text/Web pages/Internal notes/Pricing sheets/Case studies/Policies; original stored in object storage, DB stores metadata+extracted structure. Uploading pricing-old-2024.pdf doesn't immediately change pricing; becomes Knowledge Source from which candidates extracted. Candidate example "Service price=$4,000" checked vs current KB "$4,500" → conflict/review instead of silent change. Authority hierarchy: Current approved structured record > Current approved policy > Approved canonical document > Approved historical source > Unapproved document > AI extraction/inference. Knowledge conflict example pricing table $4500 vs FAQ $3900 → KnowledgeConflict; AI Sales Manager/Human Attention surfaces; until resolved autonomous commercial commitment restricted. Conflict types: VALUE_CONFLICT/TEMPORAL_CONFLICT/SCOPE_CONFLICT/POLICY_CONFLICT/DUPLICATE/AMBIGUOUS. KnowledgeGap created when AI repeatedly receives "Do you support Shopify Plus?" and approved KB has no answer. Record: question/topic/occurrence_count/affected conversations/business impact/first_seen/last_seen/status. High-frequency gaps become priority. Lifecycle: OPEN→DRAFTED→IN_REVIEW→RESOLVED. Once approved answer exists, future conversations can use. Don't hallucinate missing KB: correct ASK HUMAN or safe response that doesn't invent; wrong is AI guesses company policy.

## 58-65. Freshness + Stale + Semantic Retrieval + Chunks + Embedding Version + Chunking + Hybrid + Structured First
Every important KB item defines review_interval/last_reviewed_at/next_review_at/valid_until. Pricing tighter freshness than evergreen company description. Stale doesn't always mean false; means needs revalidation before high-authority use. For low-risk context visible with warning; for pricing/commitment: STALE→ASK/BLOCK depending policy. Semantic retrieval uses PostgreSQL + pgvector initially; no separate vector DB needed. KnowledgeChunk: knowledge_revision_id/content/embedding/content_hash/chunk_index/metadata; vector retrieval points back to exact approved revision. Embedding version: provider/model/dimension/embedding_version stored; when model changes, embeddings can be regenerated safely. Chunking not blindly every 500 chars; use semantic boundaries heading/section/FAQ/policy clause/service section/case-study result. Hybrid retrieval: structured filters + Keyword/FTS + Vector similarity + Entity filters + Scope filters + Authority + Freshness. Vector similarity alone not enough. Structured first for "What is Website Package price?" — prefer structured Pricing record, not vector-search PDFs. For "What case study best matches this landscaping prospect?" semantic retrieval more useful.

## 66-76. Context Builder + Package + Least Context + Permission + Classification + Freshness + Conflict Handling + Token Budget + Summaries + Versioning + Correction
Central service ContextBuilder: input agent/task/company/person/conversation/opportunity/goal → output minimum relevant context package. Conversation Agent example: prospect identity/company facts/relevant current signals/conversation summary/recent messages/open commitments/qualification/current opportunity/relevant memories/relevant KB/applicable policies/evidence references — not entire CRM. Least Context Principle: more context ≠ better AI; too much creates noise/cost/conflicts/privacy exposure/hallucination risk. Context Permission: does agent need it?/actor have permission?/classification allowed?/scope correct? — AI context respects same security boundaries as humans. Data classification: PUBLIC_BUSINESS/INTERNAL/CONFIDENTIAL/RESTRICTED; agents/tools declare allowed classifications. Context freshness prefers current/verified/approved/entity-specific/direct evidence over old generic memory. Context conflicts: if pricing conflict, don't hide; can say "Pricing conflict detected. Autonomous quoting prohibited." rather than arbitrarily choosing one. Token budget priority: critical current facts/current conversation/policies/open commitments/relevant KB/relevant memory/older history — low-value context excluded first. Long conversations: Rolling Conversation Summary stored but original messages remain canonical; summary derived, not replacement. Summary versioning: covers_through_message_id/generated_at/model_version; new messages extend/rebuild. Summary correction: correct derived summary/memory without deleting original message; historical source remains intact.

## 77-82. Memory Compression + Never Compress Conflicts Away + Importance + Decay + Durable Memory + Suppression Never Memory + Qualification Memory
Person with 100 small memories can consolidate compatible ones: "Asked for Tuesday meetings/Prefers Tuesday afternoons/Requested Tuesday call" → stronger summarized preference while preserving evidence links. If memories disagree, do not summarize into fake certainty; keep conflict visible. Not every sentence deserves permanent memory; importance factors: future usefulness/commercial relevance/explicit preference/commitment/decision criteria/objection/relationship change. "Thanks!" doesn't need long-term memory. Memory decay: "Busy this week" should not influence outreach 2 years later; support valid_until/decay/stale state. Other items persist longer: explicit DNC/major relationship/historical opportunity outcome — although DNC itself remains primarily in Suppression, not ordinary memory. Critical: unsubscribe must be deterministic Suppression data; never "AI remembered they unsubscribed". Qualification answers Need/Timeline/Budget/Decision maker/Current solution belong in structured Qualification tables; memory may support with evidence but shouldn't replace.

## 83-94. Opportunity Context + Person Changes Company + Entity Merge/Split + Human Correction + AI Correction + Revalidation + Cost-Aware + Pre-Outreach + Pre-Meeting + Search Examples + NL Knowledge Search + Usage Logging + Revision Impact + Rollback + Regression
If prospect has two opportunities Website redesign + SEO retainer, Context Builder must not mix budgets/objections between them. Person changes company: John OldCo ended + NewCo current; old company memories don't automatically transfer as NewCo facts; relationship history can remain useful. Entity merge: Memory/Evidence/Relationships/Conversations must be re-parented/reconciled transactionally; conflicting memory isn't silently discarded. Entity split: if mistaken merge reversed, enough provenance preserved to restore associations where possible. Reason evidence/source IDs matter. Human can "This is incorrect" → Invalidate memory/Correct value/Add reason + audit trail. AI can propose correction based on new evidence; high-impact memory changes may require domain validation/human review. Scheduled memory revalidation finds stale important memories/conflicted/old context on high-value accounts → triggers appropriate re-check. Cost-aware: don't spend premium enrichment refreshing every dormant lead monthly; prioritize active opportunities/upcoming meetings/active campaigns/high-priority accounts. Before contacting stale lead: critical company facts stale?/person still employed?/email still valid?/relevant signals fresh? → revalidate. Pre-meeting: latest conversation/open commitments/opportunity stage/recent signals/stakeholders/outstanding questions → updated brief. NL query: "Kis prospect ne kaha tha ke January ke baad contact karna?" → structured memory + semantic retrieval, results show evidence. User: "Hamari SEO service ki approved pricing kya hai?" → answer from approved structured KB + show source/version, not general model knowledge. Knowledge usage logging: important autonomous communication records which KB revisions supported response; e.g. Message 123 used Pricing v7/Service v4/FAQ v11. Pricing v7→v8: previous emails historically linked to v7; future replies use v8. Rollback if v8 wrong: don't mutate historical v7/v8; rollback/republish v7 or corrected v9. Knowledge regression testing before publishing important change: sample questions "What does package include?/What's the price?/Do you offer refunds?/How long does delivery take?" → compare expected approved behavior. AI policy regression especially pricing/discounts/guarantees/refunds/contract terms/delivery commitments so KB update doesn't unexpectedly authorize bad replies.

## 114-120. Data Retention + Sensitive Transcripts + Privacy-Aware Memory + Export + Deletion + Embedding Deletion + Re-Embedding + Context Cache
Different retention: raw extraction candidates/old snapshots/conversation messages/meeting transcripts/approved KB/audit/memory according to workspace/security policies — not one universal retention. Transcripts need provider availability/permissions/retention controls and should extract only useful business memory; no indefinite everything-storage. Privacy-aware memory: avoid storing irrelevant sensitive personal information; purpose is commercial relationship context, not invasive personal profiles. Authorized memory/knowledge export distinguishes Canonical facts/Memories/Notes/Conversation history/AI inferences so downstream user understands provenance. Person data deletion includes person-linked memory/relationship links/derived embeddings/search indexes; suppression minimum identifier may be treated separately under configured legal/operational policy. Deleting underlying content must also invalidate/delete vector representation — no orphan semantic memory. Re-embedding: content_hash changes → regenerate embedding; no need to regenerate unchanged chunks. Context packages can be briefly cached for performance; high-risk actions re-fetch critical current state: Pricing/Suppression/Approval/Calendar availability/Kill switch — never trust stale context cache for execution authority.

## 121-126. Conversation Agent Example + Lead Hunter Example + Not-Now + Referral + Memory Doesn't Auto-Create Facts + Knowledge Doesn't Override Suppression/Policy
Conversation: prospect asks "Can you do it for $3,500 and finish by Friday?" → Context Builder retrieves current approved pricing/discount authority/delivery policy/service scope/opportunity context/previous commitments/conversation history → AI identifies discount request + delivery commitment request → Policy determines ASK; AI doesn't invent agreement. Lead Hunter: ABC Landscaping discovered → research produces Website Fact/Owner candidate/Technology Fact/Recent Signal/Opportunity Hypothesis; memory is not abused as dumping ground for all research; each goes to correct data layer. Not-Now: "Reach back out in February" → Conversation memory + Contact-later structured state + possibly commitment/task/scheduled nurture; before February Policy→WAIT; at due date revalidate company/contact→Next Best Action. Referral: "Sarah handles this now. Email her instead." → candidates for Person Sarah/Employment or role/Referral relationship/Wrong-person classification for current person/Next Best Action; evidence remains original message. Casual "We're probably around 50 people now" → Fact Candidate/Evidence with appropriate confidence; don't silently set employee_count=50 as verified truth. KB "Discounts are sometimes available" cannot authorize AI to issue 20% discount; commercial authority remains Policy Engine. KB "Follow up aggressively" does not override Suppression UNSUBSCRIBED; result BLOCK always. Memory "John prefers email" doesn't override current inbound "Don't email me anymore"; current explicit statement wins and creates suppression.

## 132-134. Locked Memory Rules + Locked Knowledge Rules + Locked AI Context Rules
Memory rules: Messages are not memory. Facts are not memory. Signals are not memory. AI hypotheses are not facts. Strategy learning is not prospect memory. Memory is entity-scoped. Important memory has provenance. Memory can expire/become stale. Conflicting memories are preserved and resolved. AI extraction does not directly mutate canonical truth. Commitments get dedicated structured entities. Suppression never relies on AI memory. Relationship Graph is structured. Employment remains specialized. Human corrections preserve audit history. Knowledge rules: Uploaded documents are sources, not automatic truth. AI-created knowledge starts as candidate/draft. Approved knowledge is versioned. Pricing is structured. Services are structured. Claims require evidence/approval. Conflicting knowledge blocks unsafe autonomous use. Knowledge gaps explicitly tracked. Important knowledge has freshness/review lifecycle. Historical revisions remain available. Semantic similarity never overrides authority. Current approved structured data beats old documents. KB cannot grant AI commercial authority. KB cannot override Policy/Suppression. Every important autonomous answer can trace which KB version supported it. Context rules: Agents receive minimum necessary context. Context is entity- and task-specific. Permissions apply before retrieval. Sensitive classification applies to AI too. Current/fresh information preferred. Conflicts shown, not hidden. Structured data preferred for structured questions. Vector search is retrieval support—not truth. Critical execution state re-read before action. AI never receives credentials/secrets. Context usage traceable without storing private chain-of-thought. Original evidence remains canonical even when summaries regenerated.
