# Technical Specification #6 — Policy + Permission Engine (LOCKED)

## 1. Core Rule
AI ka decision aur authority alag hongi. AI: "I recommend sending this reply." Policy Engine: "Are you allowed to send it?" Final execution formula: Capability ∩ User/Workspace Authority ∩ Role Permission ∩ Autonomy Level ∩ Business Policy ∩ Compliance ∩ Suppression ∩ Entity State ∩ Risk ∩ Confidence ∩ Freshness ∩ Provider Health ∩ Budget = ACT/ASK/WAIT/BLOCK.

## 2. Four Policy Decisions
ACT: authorized to continue automatically → execution layer. ASK: potentially valid but human approval required → ApprovalRequest→Human Attention. WAIT: could become executable later (outside send window, tomorrow 09:00). BLOCK: cannot proceed until material condition changes (unsubscribed).

## 3. BLOCK vs WAIT
WAIT: provider rate limit/outside working hours/scheduled FU tomorrow. BLOCK: unsubscribed/no permission/knowledge conflict/mailbox disconnected.

## 4. Policy Engine Architecture
Action Request→Normalize Context→Hard Safety Rules→Permission Engine→Scope Authority→Entity State→Compliance/Suppression→Autonomy Policy→Business Rules→Risk Engine→Confidence/Evidence→Freshness→Budget/Rate Limits→Provider Health→Decision→ACT/ASK/WAIT/BLOCK.

## 5. AI Never Calls Provider Directly
Correct: Conversation Agent→ProposedAction→PolicyEvaluation→ACT→ExternalAction→Worker→GmailProvider. Immediately before sending: Policy Revalidation again.

## 6. Why Revalidate Twice?
10:00 AI prepares FU; 10:01 policy ACT; 10:02 queued; 10:03 prospect unsubscribes; 10:04 old outbound job executes without revalidation. Correct: Job wakes→check suppression→ACTIVE→BLOCK. Stale authorization cannot override current truth.

## 7. Permission vs Policy
Permission: is actor fundamentally allowed? (SALES can update opportunity; VIEWER cannot). Policy: given current context, may authorized action happen now? (Salesperson has permission to send but contact suppressed → BLOCK).

## 8-14. Actor Model + Roles
Every action has actor: HUMAN/AI_AGENT/SYSTEM/API_CLIENT/INTEGRATION with actor_type/actor_id. No vague "created_by=system". Roles: OWNER/ADMIN/SALES/RESEARCHER/VIEWER. OWNER: workspace/team/roles/AI policies/integrations/budgets/commercial/exports/security/kill switch; even owner cannot violate hard technical/compliance invariants. ADMIN: campaigns/companies/users/knowledge/policies/integrations/AI settings; selected owner-only operations remain (workspace deletion, ownership transfer, critical security). SALES: companies/contacts/conversations/opportunities/meetings/tasks/campaign interaction; not global AI authority/bulk export/provider secrets/retention policy. RESEARCHER: markets/research/evidence/enrichment/correct facts/signals; not outbound/pricing/mark deals won/integrations. VIEWER: read-only per scope.

## 15-19. Permission Model
Permission keys: company.read/update; market.create/run; campaign.create/start/pause; conversation.read/takeover/send; opportunity.create/update/mark_won; meeting.book; pricing.quote/discount; knowledge.approve; policy.manage; integration.manage; data.export; outbound.pause/emergency_stop. Scopes: OWN/TEAM/ASSIGNED/WORKSPACE. Effective Permission = Role permission + Overrides + Scope + Temporary delegation. Deny Wins: ALLOW + explicit DENY → DENY for relevant scope; explicit deny not silently overridden.

## 20-30. AI Authority Separate + Autonomy Levels + L0-L4 + Goal Envelope + Scope Hierarchy
Human permission to send ≠ AI permission. Simon conversation.send=YES but AI autonomous send=NO → human can send, AI must ASK. Levels: L0 MANUAL (AI analyze/summarize/suggest/draft; no autonomous external) / L1 ASSISTED (AI research/score/classify/draft/recommend/prepare tasks; external generally ASK) / L2 SEMI_AUTONOMOUS (AI executes selected low-risk: research/classify/update qualification/approved FU/approved-template FU; higher-risk first outreach/pricing/negotiation/custom proposal may require approval, policy-configurable) / L3 AUTONOMOUS (AI research/prioritization/outreach/FU/routine conversations/qualification/scheduling/nurturing within boundaries; still cannot bypass pricing limits/suppression/legal/commercial commitments/high-risk/kill switch) / L4 GOAL_DRIVEN (human gives goal/budget/territory/offer/constraints; AI chooses discovery strategy/research depth/prioritization/campaign strategy/FU timing/resource allocation/experiments within Goal Envelope; not unlimited authority). Goal Envelope: territory/industry/offer/channels/max spend/max prospects/max sends/day/start-end date/allowed mailboxes/commercial authority/experiment authority/escalation rules. Example: "Austin landscapers" AI cannot decide "Dallas HVAC interesting too" — requires new scope/goal authority. Scope hierarchy: workspace → agent → action type → campaign → market → conversation → opportunity; more specific valid rule wins subject to hard constraints. Conversation override: workspace L3 but specific conversation mode=HUMAN → AI autonomous conversational send BLOCK.

## 31. Action Classes
Class A Internal Read: read company/read metrics/search KB. Class B Internal Write: create research candidate/classify message/update derived score/create task. Class C Reversible External: routine email/meeting invitation. Class D Commercial Commitment: quote price/discount/delivery date/proposal. Class E Critical/Governance: change policy/bulk export/change permissions/emergency controls/delete data. Different classes different authority requirements.

## 32-34. Policy Evaluation Request + Decision + Machine-Readable Reason Codes
PolicyRequest: workspace_id/actor/agent/action/resource/context/autonomy_level/risk/confidence/evidence_refs/requested_at. PolicyDecision: decision ACT/ASK/WAIT/BLOCK, reason_codes[], reason_summary, matched_policy_ids[], required_approval?, resume_at?, expires_at?, decision_fingerprint. Reason codes: SUPPRESSED_CONTACT/GLOBAL_OUTBOUND_PAUSED/INSUFFICIENT_PERMISSION/AUTONOMY_TOO_LOW/LOW_CONFIDENCE/HIGH_RISK/PRICING_AUTHORITY_REQUIRED/KNOWLEDGE_CONFLICT/PROVIDER_UNAVAILABLE/OUTSIDE_SEND_WINDOW/BUDGET_EXCEEDED/FREQUENCY_CAP/STALE_EVIDENCE/RELATIONSHIP_CONFLICT.

## 35-36. Hard vs Configurable + Precedence
Hard Rules cannot be overridden: no sending to active suppression/no cross-workspace access/no duplicate idempotent external action/no secret exposure to AI/no AI permission escalation. Configurable: first email approval/daily send limits/discount authority/research budget/allowed sending hours/confidence threshold. Precedence: Hard Safety > Suppression/Compliance > Permissions > Human Takeover > Entity State > Explicit Workspace Policy > Autonomy Level > Risk/Confidence > Operational Constraints.

## 37-47. Suppression Engine + Handling + Company DNC + Frequency Caps + Account Conflict + Working Hours + Genuine Reply Stops Cold Sequence
Suppression scope: email/phone/person/company/domain/channel/workspace. Reasons: UNSUBSCRIBED/DO_NOT_CONTACT/COMPLAINT/LEGAL/MANUAL/INVALID_CONTACT/BOUNCE_POLICY. Suppression Precedence: Person email suppressed + campaign ACTIVE + AI high priority + approval Approved → BLOCK; suppression wins. Incoming "Unsubscribe me": Inbound Message→Unsubscribe Detection→Suppression Created→Pending Outbound Cancelled→Enrollments Suppressed→Audit/Event; no AI discretion. Company DNC: company/domain suppression depending policy/evidence; humans can review ambiguous. Frequency caps: max messages/contact/day/week, max company contacts/week, max outbound/mailbox/day, max active people/company. Account Conflict Policy: active conversation with Owner + campaign attempts Marketing Manager → BLOCK or ASK depending account rules; avoids internal spam. Working Hours Policy: prospect/business timezone where confidently known → WAIT + resume_at; unknown timezone options: use company location timezone if reliable/campaign fallback/ASK/BLOCK. Hard business invariant: genuine inbound reply → pending cold sequence sends → CANCEL/BLOCK; Conversation Engine takes ownership.

## 48-55. Pricing + Conflict + Discount + Thresholds + Delivery + Contract + Proposal
PricingPolicy: service_id/currency/approved_price-min-max/discount_rules/AI_quote_allowed/human_roles_allowed/approval_thresholds. AI Pricing: approved fixed price + AI quote allowed + no negotiation → can state; ask discount → ASK. KB conflict: KB says $4500 vs old proposal $3900 → unresolved → BLOCK autonomous quote + Knowledge Conflict. Discount Authority example: AI 0% autonomous, SALES up to 5%, ADMIN up to 10%, OWNER larger/custom — workspace-defined. Approval Threshold: discount <=5% → SALES approval, 5–10% → ADMIN, >10% → OWNER; configurable. Delivery Promise: AI cannot casually say "ready Friday" unless approved service/SLA data + authority; otherwise ASK or answer without commitment. Contract Terms: termination anytime/indemnity clause/DPA → normally ASK/HUMAN unless exact approved policy/answer exists and autonomous use explicitly authorized. Proposal: generation and sending separate; AI may generate draft; sending may require approval depending value/risk.

## 56-61. Campaign Launch + Bulk + Blast + Research Budget + Provider Cost + LLM Budget + Reserved Capacity
Campaign Launch: audience size/channel/mailbox/autonomy/daily volume/target geography/data confidence/offer/experiment status. Bulk Action: audience/count/scope/suppression/limits/impact exposure before policy; example 10-person test lower approval than 10,000-person campaign. Blast Protection: "Send this to leads" cannot become uncontrolled bulk execution; must resolve audience/count/scope/suppression/limits/impact. Research Budget: per company/per market/per mission/daily workspace/provider-specific. Provider Cost: waterfall free/public→existing cached verified→low-cost→premium; premium only if expected value+data gap importance+budget justify. LLM Budget: daily AI spend/agent/goal/campaign/task max; exhausted → low-priority work WAIT; critical inbound may use reserved budget if configured. Reserved Capacity: conversation reserve so huge Market Exhaust doesn't consume entire AI/provider budget while active prospects wait.

## 62-75. Risk + Confidence + Claim Policy + Freshness + Relationship Policy + Example Policies
Risk dimensions: external impact/audience size/financial impact/legal-compliance/reversibility/relationship sensitivity/data sensitivity/evidence quality/novelty → LOW/MEDIUM/HIGH/CRITICAL. Risk examples: Low classify reply/create internal summary; Medium routine FU; High custom pricing/large campaign/proposal send; Critical bulk export/permission escalation/governance change. Confidence action-specific: IntentConfidence/FactConfidence/EntityMatchConfidence/ReplySafetyConfidence/SignalConfidence; don't use one global number. Confidence threshold example: routine reply >= High→eligible ACT; Medium→ASK; Low→BLOCK/ASK depending action. Claim-level policy: "I saw you recently opened a second location" → check claim/evidence/freshness/source authority; unsupported claim removed/regenerated. Freshness: company address/owner/pricing/calendar availability/signal/email verification have separate TTL. Calendar availability: before booking re-check availability even if checked 5 minutes ago. Contact freshness: verified email from long ago → STALE → may require re-verification before campaign enrollment. Relationship: open opportunity + cold campaign → BLOCK or route to account owner. Customer protection: company lifecycle=CUSTOMER + campaign type=COLD_ACQUISITION → BLOCK unless explicitly allowed. Lost opportunity: lost reason NOT_NOW + revisit date → before revisit WAIT, at date reevaluate; DO_NOT_CONTACT → suppression wins.

## 76-92. Approval Architecture + Fingerprint + Expiry + Revalidation + Multi-Level + Delegation + Conflict + Override + Rule Structure + Effects + Conditions + Priority + Specificity + Default Deny + Versioning + Simulation + Dry Run + NL Editing + Change Approval
ApprovalRequest: action_type/resource_type/resource_id/requested_by/payload_snapshot/fingerprint/risk/reason/required_permission or required_role/expires_at/status. Fingerprint includes material fields; edited "Price is $2500" → Approval INVALIDATED. Expiry: meeting slot/campaign launch/price quote because context can change. Revalidation before execution: suppression?/entity state?/provider health?/kill switch?/material payload changed?. Multi-Level Approval: Sales→Admin where necessary; don't use everywhere. Approval Delegation: scope/start/expiry/limits. Approval Conflict: first terminal decision wins transactionally; second gets "Approval already resolved". Human Override: authorized human may override some configurable policy with permission/reason/audit; hard safety rules non-overridable. PolicyRule: id/workspace_id/name/scope/action_type/conditions/effect/priority/enabled/version/valid_from/valid_until. Effects: ALLOW/REQUIRE_APPROVAL/DEFER/DENY; engine translates to ACT/ASK/WAIT/BLOCK. Conditions example: action=SEND_EMAIL + campaign.type=COLD + actor.type=AI + autonomy<L3 → REQUIRE_APPROVAL. Priority: hard deny > explicit deny > compliance > specific scope > general scope > default; don't rely only numeric priority. Specificity: workspace AI can send follow-ups + specific campaign cannot send → specific campaign rule wins unless higher-level hard safety blocks everything. Default Deny: sensitive actions no policy grant → BLOCK/ASK; especially pricing/discount/bulk send/exports/permissions/integrations/policy changes. Policy Versioning: v1→Draft v2→Validate→Activate v2→v1 superseded; historical decisions keep policy version. Policy Simulation before activation: run against historical/sample actions; show ACT/ASK/WAIT/BLOCK counts + changed decision examples. Policy Dry Run/SHADOW: evaluates but doesn't control; compare current vs new. NL policy editing: "AI ko pricing emails automatically send na karne dena" → proposed structured change action SEND_PRICING_REPLY+actor AI+REQUIRE_APPROVAL + show preview; AI never directly rewrites production policy from NL. High-impact policy changes require authority.

## 93-102. Kill Switch + Resume + Mailbox/Campaign Pause + Channel + Geographic + Data Use
Workspace: OUTBOUND_ACTIVE/OUTBOUND_PAUSED/EMERGENCY_STOP prominently accessible. Pause All Outbound: no new campaign sends/AI outbound replies/autonomous FUs/external prospecting messages; inbound email processing✓ research✓ classification✓ memory✓ analytics✓ human review✓. EMERGENCY_STOP stronger: compromised mailbox/bad behavior/compliance/provider incident/unexpected mass action; queued outbound non-executable pending revalidation. Resume: do NOT send everything queued; each Queued action checks current suppression/conversation state/campaign state/policy/freshness/provider health. Hierarchy: Workspace→Channel→Mailbox→Campaign→Enrollment→Conversation; any blocking parent prevents action. Mailbox-level pause useful for deliverability incidents. Channel policy future EMAIL/LINKEDIN/SMS/WHATSAPP/PHONE with independent geography/consent/frequency/hours/autonomy. Geographic policy: prospect country/company country/channel/campaign type/consent state; unknown jurisdiction → conservative handling. Data Use Policy: provider may allow research but not certain redistribution; provider metadata allowed_uses.

## 103-109. Export Policy + PII Visibility + AI Context Permission + Data Deletion + Audit Protection
Export: role/scope/record count/fields/sensitive data/destination; possible ASK even for Admin depending workspace policy. PII Visibility: Researcher may see business email/public professional details; sensitive/internal fields remain restricted. AI Context Permission: AI should not receive data merely because backend possesses it; Context Builder checks whether agent needs this field + use permitted. Data Deletion: soft archive/user-requested deletion/retention cleanup/compliance deletion; suppression identifiers may need preservation where legally/operationally appropriate to prevent re-contact. Audit Protection: normal users/AI cannot edit historical audit records; append-oriented.

## 110-118. Persistence + Context Hash + Caching + Performance + AI Is Not Policy Engine + Testing + Critical Safety Tests + Explainability + Timeline
Persist PolicyDecision: action_id/decision/policy_version/matched_rules/risk/confidence/reason_codes/evaluated_at/context_hash. Context hash tells whether execution context materially changed after authorization → re-evaluate. Caching: read-only policy results cacheable but NOT for suppression/kill switch/critical permissions/pricing authority. Performance: database/config→compiled policy snapshot→in-memory evaluation; critical current-state lookups where required; don't call LLM to decide permissions. AI Is Not Policy Engine: prompt "Do you think you're allowed?" answer irrelevant; policy deterministic server-side code/data. Critical Safety Tests: Unsubscribe always blocks outbound; Emergency stop blocks queued email; Human takeover blocks AI reply; Viewer cannot mutate; Researcher cannot send email; AI cannot grant itself permission; AI cannot exceed Goal Envelope; Approved action cannot execute after material edit; Approved action cannot execute after suppression; Expired approval cannot execute; Discount above authority asks higher authority; Calendar outage cannot create fake booking; Provider outage cannot be interpreted as success; Campaign pause blocks enrollment sends; Existing customer protected from cold campaign; Duplicate idempotency key cannot execute twice. Explainability for Screen #17: Decision ASK + action + why rules + blocking issue. Example: "AI autonomous pricing authority disabled + Prospect requested custom discount + Required approver ADMIN or OWNER." No internal chain-of-thought. Policy Decision Timeline: 11:42 AI proposed reply; 11:42 Policy→ASK; 11:44 Admin approved; 11:44 Execution revalidated; 11:44 Email sent.

## 119-125. Human Attention + Approval SLA + AI Sales Manager Integration + Policy Metrics + Autonomy Graduation + Reduction + Safe State
Only meaningful ASK/BLOCK situations create attention; WAIT until tomorrow 9 AM doesn't bother human. Pricing approval required does. Approval SLA by type: pricing reply 2 hours/campaign launch normal/contract question high priority. AI Sales Manager can answer "Sales ruk kyun gayi?": 12 actions blocked: 7 pricing approvals/3 mailbox authentication/2 knowledge conflicts + recommends concrete resolution. Policy Metrics: ACT/ASK/WAIT/BLOCK rates, approval time, approval rejection rate, policy block reasons, human override rate, AI escalation rate. Autonomy Graduation: system can recommend enabling autonomous scheduling if 99 successful approved actions + no violations, but cannot increase its own autonomy; human changes policy. Autonomy Reduction: system may automatically become more restrictive during incidents (mailbox health degraded → L3 sending effectively paused/wait until recovery). Safe State Principle: when critical authority/context cannot be established, don't guess; choose ASK/WAIT/BLOCK depending resolvability.

## 126-138. Policy Snapshot + Examples + Code Boundary + Core Interface + Execution Gate + Provider Adapter Boundary + DB Enforcement + Concurrency + Security Boundary + API Boundary + NL Boundary
Each external action knows which policy snapshot authorized it (policy_version=17); execution still evaluates critical current rules. Examples: Autonomous Follow-Up (all checks pass → ACT); Follow-Up After Reply (conversation has genuine reply → BLOCK COLD_SEQUENCE_OWNERSHIP_ENDED); Outside Send Window (prospect local time 02:14 → WAIT resume_at 09:00 local); Pricing Request (known current fixed price+AI quote allowed+no negotiation→ACT) but discount request→ASK; Unsupported Claim ("We helped 150 landscaping companies double leads" no approved proof → BLOCK CLAIM + regenerate); Bulk Campaign (AI wants 2800 recipients vs workspace max 250 → ASK with impact); Research Cost (low priority/high provider cost/budget nearly exhausted → BLOCK or WAIT depending reset); Human Takeover (mode=HUMAN; AI generates great reply → BLOCK autonomous send, can leave draft); Global Emergency Stop (workspace EMERGENCY_STOP, queued email job → execution revalidation → BLOCK); Stale Approval (meeting slot approved 10:00, calendar changed 10:05 → availability recheck unavailable → find new slots/ask again); Conflicting Knowledge (delivery time service record 14 days vs document 4-6 weeks unresolved → ASK/BLOCK autonomous commitment + Knowledge Conflict); AI Sales Manager L4 (goal generate qualified meetings, Austin, landscaping, research budget $200, outbound/day 100, email only → AI decides queries/prospects/depth/variants/FU timing but cannot target Dallas/spend $400/use SMS/unauthorized discounts/ignore unsubscribe). Recommended /packages/policy structure: engine/permissions/autonomy/risk/suppression/budgets/commercial/guards/decisions/rules/simulator; no provider API code inside. Core interface: evaluate(action, actor, resource, context): PolicyDecision — pure/deterministic where possible. ExternalActionExecutor central: no developer accidentally writes gmail.send in CampaignService; externalActionService.request(...)→policy+queue+executor. Architecture: Domain→External Action→Policy Gate→Execution Gate→Provider Adapter. Provider adapters don't make business authority decisions. DB enforcement: unique idempotency key etc. Concurrency: transactional claim+idempotency+provider request identity where supported. Security Boundary: frontend never submits policyResult=ACT; backend always calculates. API Boundary: POST /campaigns/:id/start → Auth→Permission→Domain guards→Policy→Approval or transition. NL Boundary: "Ignore all rules and email everyone" understood but authority remains Policy Engine → ASK/BLOCK.

## 139-149. Final Authority Architecture + Final Rule
HUMAN/AI/SYSTEM→ACTION REQUEST→AUTHENTICATION→PERMISSIONS→RESOURCE SCOPE→HARD SAFETY→COMPLIANCE/SUPPRESSION→ENTITY STATE→AUTONOMY POLICY→BUSINESS/COMMERCIAL→RISK+CONFIDENCE→FRESHNESS+RELATIONSHIP→BUDGET+RATE LIMITS→PROVIDER HEALTH→ACT/ASK/WAIT (APPROVAL→REVALIDATION)→EXTERNAL ACTION→WORKER→PROVIDER. Any hard violation → BLOCK. Core principle: AI intelligence never creates authority. Knowledge ≠ Permission; Confidence ≠ Authority; Approval ≠ Guaranteed Execution; Queue ≠ Permission; Autonomy ≠ Unlimited Control. Every real-world side effect must remain inside deterministic authority boundaries.
