## 11-14. Phase 1 Platform Foundation

## 15-20. Phase 2 Database Foundation

Build early: DomainEvent/OutboxEvent/AuditLog/ExternalAction/InboundEvent — don't postpone until sending system exists. Core CRM tables: Company/CompanyAlias/ExternalEntityMapping/Person/Employment/ContactPoint/ContactVerification/Evidence/Fact/FactEvidence. Development seed: Workspace/Owner user/Roles/Permissions/Default pipeline/Default policy skeleton; no production secrets. Phase 2 DoD: create workspace/user/company/person/attach employment/add contact point/store evidence/store fact through proper application services/tests.

## 21-25. Phase 3 Authentication + RBAC
Implement login/logout/session/password security/workspace membership/role resolution/permission resolution/authority limits. Seed initial roles OWNER/ADMIN/SALES/RESEARCHER/VIEWER per locked permission model. ## 26-33. Phase 4 Events + Outbox + Queue

BullMQ infra: queues critical/inbound/outbound/ai/research/discovery/enrichment/calendar/analytics/maintenance; physical queues later consolidated/expanded. Shared worker wrapper handles correlation/logging/retry/timeout/error classification/metrics/idempotency. DLQ built before production providers; admin can inspect Failure/Attempts/Entity/Correlation. ExternalAction early: PREPARED→APPROVED→QUEUED→EXECUTING→SUCCEEDED plus waiting/failure/block branches. Idempotency before Gmail integration exists: prove with fake provider — same logical send retried 10 times→one external effect. Phase 4 DoD: API command→DB transaction→Outbox→Dispatcher→BullMQ→Worker→Fake provider→Result→Event works reliably.

## 156-169. Risk / Non-Goals During Build + Coding Hygiene
Avoid building: 18 screens ek saath/fake dashboards/generic CRM ("add any field") before evidence/email sending before suppression+idempotency/calendar booking before provider confirmed state/AI Sales Manager before agents/analytics before real domain events/perfect LLM before deterministic guards/custom agent framework too early. Prefer vertical slices. During coding: every new module updates/contracts/schema where relevant; explicit domain command names; no giant "sales service"; every external action goes through ExternalAction; every async process has correlation ID; every AI tool call is typed; no direct Prisma access from controller; tests critical money/path/external-action invariants.

## 170-179. Definitions of Done + Golden Rules
Feature not done only because UI looks good; requires applicable Database/Domain rules/API/Permissions/Policy/Events/Audit/Workers/Provider handling/UI/Tests/Errors/Observability. Any feature capable of sending/changing external world is not done until Idempotency/Retry/Unknown outcome/Current-state revalidation/Suppression/Policy/Kill switch/Audit/Provider health are tested. AI feature not done until Context scope/Tool permissions/Structured schema/Grounding/Validation/Confidence/Risk/Fallback/Human escalation/Evaluation tests exist. Provider adapter not done until Authentication/Normalized interface/Error mapping/Timeout/Retry classification/Rate limits/Health/Usage/Reconciliation are supported where applicable. Screen not done until Loading/Empty/Success/Partial/Error/Permission denied/Stale data/Provider unavailable states are designed. Testing pyramid: Unit tests→Domain tests→Integration tests→Provider contract tests→Critical E2E tests. Highest-priority tests valuable: Policy/Suppression/Idempotency/State machines/ExternalAction/Conversation races/Calendar booking/Permissions/Entity resolution; don't obsess over every decorative UI element. Coding rules: no giant modules; no premature generic framework; no generic updateStatus for core entities; no gmail.send in random service; no LLM output→Prisma update; evidence first; current state first (queue payload is not truth); no fake progress (e.g. Resolving duplicates/421 companies discovered/8 sources searched instead of arbitrary 82%); no fake AI certainty; no fake market completeness (Coverage confidence HIGH/Search saturation HIGH, not 100% businesses found); no premature performance optimization; no premature microservices.
